## 联机适配范围

**Observed**（源代码）：

- 上游 AI、感知、急救、奴隶、招募、战斗、尸体处理、生产、农田和保存修复由服务端执行。
  地上物品同区重新放置保留新位置与旋转；蹲姿保留当前动作目标；异步寻路异常返回失败，保留 Coop 玩家优先队列和请求生命周期。
- 任务注视目标进入授权角色快照及二进制增量；目标在观察区域外时只显示朝向，不披露其距离。
  暂停悬停同样通过已发布角色校验。工作工具、机器待机与物品尺寸、农田收获进度沿用各自的状态组件。
- 状态效果只在服务器施加属性和计时，客户端接收首选角色或检查目标的显示数据。
  长说明及修饰定义和层数、剩余时间分开；通过服务器 tick 推算倒计时，重复移除／施加复用定义。
  普通组件批次及运动包采用独立无损压缩，保持原有频率、精度和可靠校正。
- 模组数据阶段仅执行本地已信任的代码，先修改合并数据库，再建立派生内容；客户端编解码和绘制共享同一数据库。
  两端独立重算修改指纹并纳入握手；启用的 RE_Kenshi 配置、最终重绑定目标及显式 gameplay 文件也纳入证据。
  新世界／读档就绪回调在完整世界准备后执行，恢复候选不触碰当前活动世界。
- 模组小队的独立钱包、人数上限豁免和休眠按实际派系保存、执行；未加载的持久角色仍计入相应人数和小队容量。
  普通玩家不能伪造模组专属命令。缺失模组时恢复队伍控制、人数计算与休眠状态，钱包只转入原派系国库。
  联机休眠依据各玩家实际指挥角色的位置，客户端相机不改变共享模拟。
- 交易价格过滤器接入逐玩家交互；柜台和 NPC 消费识别全部玩家派系，收入进入真实拥有者的钱包。
  库存副本逐操作对账，保留权限、买回凭证、角色与库存版本、拖拽物品归还，以及逐玩家关闭通知。
- 城镇建筑、布局机器、电池、农田和废墟保持 Coop 的 canonical ID 与单一原生保存路径。
  旧家具库存首次迁移须写入原生记录后才移除旧副本；未修改的原生库存记录保持不变。
- 导航及植被保留每个世界的所有权快照、generation、incarnation、取消和发布边界。
  动态所有权改用匹配的布局缓存；同步 ragdoll 几何仍保留工作线程资源生命周期。
  导航先捕获区域环再清理缓存，高度图定位与读取串行化，导航缓存版本为 65。
- `AnimalMovesFix`、`PrisonPoseFix`、`GroundRepair` 与既有玩法规则共同由服务端配置和握手。
  地形修复在两端打开地形前配置。远程设置只读；照片模式的新姿态、灯光、滤镜和输出尺寸保持本地展示，不能暂停服务器。
- 启动器、图形、音频、编辑器、反馈、配置原子写入和模组工坊功能纳入，保留 Coop 名称、发行源、隔离配置和多客户端支持。
  模组引用包使用独立的 `MeitouCoop.References`，包含 Coop 的七个程序集；发布仍需该仓库自己的 NuGet 配置。

Coop 的离线饥饿暂停、空手受击经验、被奴役玩家队伍归属、笼内物品丢弃与拾取、门锁协作、报警／群战 CPU 优化、
诊断收集、Steam 显示、连接前隔离模组同步及联机多小队开局保留。
自加补丁及回归上游条件：[空手受击经验](game/character-stats.md#levelling-xp)。

逐字段往返一致。500 个全战斗角色的运动与注视合成场景，未启用本轮无损压缩时约 711.10 KiB/s；
分散位置、不同运动方向与速度、不可预测注视目标的压缩后场景约 405.04 KiB/s（含反向 ACK）。
按每条应用消息另预留 96 字节计算约 460.80 KiB/s；该预留是预算模型，不是真实 QUIC 包头实测。

500 KiB/s/玩家是优化目标，不是新增硬限速；同步频率、数值精度、可靠校正和重传语义保持不变。

235 项跳过包含原版内容与存档、Vulkan 1.3、原生 QUIC／Windows 及配置条件相关用例，不能视为通过。
真实多客户端联机、混合玩法流量、丢包重传、长期存档迁移和 GPU／音频效果仍需在真实 Kenshi 环境验收。
